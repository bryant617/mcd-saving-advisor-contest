# 麦麦省钱参谋 · 省钱策略与方法论

本文件给出「怎么才算把钱省到位」的可执行方法，配合 SKILL.md 的工作流使用。核心不是调通接口，而是**用对券、凑对单、比出最优**。

## 1. 最优用券匹配思路

目标：在用户已选商品 + 已领/可领券集合下，找出到手价最低方案。

步骤：
1. **基准价**：先不带任何券调 `calculate-price`，得到无券总价（分，÷100 转元）。
2. **单券试算（券↔商品严格绑定，通用约束）**：每张券只对它**专属券商品 code** 生效，把 `couponId`/`couponCode` 配到不匹配的商品会直接报 `600012 当前优惠券不可用！` / `促销规则不支持该商品`。匹配方法：先用 `query_meals` 拿餐品名，把券名与菜单**近似同名**商品对应（例如某「X元指定饮品券」对应菜单中同名指定饮品商品的 code），用该 code 试算；返回 600012 说明绑定的不是这个 code（可能是券专属 SKU，不在常规菜单），如实标注「该券不适用于此商品」，不假装成功。**示例（仅说明约束，实际以运行时返回为准）**：某「X元指定饮品券」与其绑定饮品 code 匹配成功、到手价即券面价；把「免费小食券」套到常规小食 code、把「套餐券」套到常规套餐 code 均报 600012。券名与商品 code 均来自工具实时返回，本技能不预置任何具体券码或商品码。
3. **组合试算（受控）**：若用户有多件不同商品、且存在「满减券 + 折扣券」可叠加可能，仅穷举**少量高概率候选组合**（如 2~3 种），不要全排列爆炸。优先试：单张最强券、满减券凑单后、折扣券叠加。
4. **选优**：取最低到手价方案，记录省了多少（基准价 − 方案价）。
5. **呈现**：用对比表（见 §4）展示，标注推荐方案与理由，最终选择权交给用户。

经验法则：
- 折扣券（如 8.8 折）对高价单更划算；满减券（如满 50 减 10）对低单价多件单更划算——据此优先试算。
- 先按「商品总额是否过满减门槛」判断是否值得凑单，再决定用哪张券。

## 2. 团餐满减 / 满折凑单分析（beType=6）

`query-promotions` 返回原始规则，需本技能自行解读：

- `promotionType`：31=满额减（如满 200 减 30），33=订单折扣（如 9 折）。
- `ruleCategory`：30=满折/折扣，40=满减。
- `products.type`：1=仅适用下列餐品，2=不适用下列餐品（即其余都适用），3=全部餐品适用。
- 解读流程：
  1. 过滤掉 `products` 限制与用户所选餐品无交集的规则。
  2. 对剩余规则，按用户已选商品总额判断是否达门槛。
  3. 若未达满减门槛但接近，给出「再加 X 元/1 件商品即可减 Y」的凑单建议（用 `query_meals` 推荐低价加购项）。
  4. 折扣类规则直接按折扣率算预计节省。
- 输出：当前可用的满减/满折清单 + 用户单是否满足 + 不满足时的凑单动作。

## 3. 套餐 / 团餐搭配区间（来自 query_meals 官方建议）

给用户搭配套餐时参考以下人均区间（企业团餐场景）：

| 人均预算 | 推荐结构 |
|---------|---------|
| 20 元以下 | 小食 |
| 20–30 元 | 汉堡 + 小食 或 汉堡 + 饮料 |
| 30–40 元 | 汉堡 + 薯条/小食 + 饮料 |
| 40–50 元 | 汉堡 + 薯条 + 小食 + 饮料 |
| 50 元以上 | 丰富组合，优先不重复小食 |

应用：当用户说「人均 35 帮我配」，按 30–40 区间给出「汉堡+薯条/小食+饮料」组合，再用 `calculate-price` 验证总价落在预算内，超了就调低某单项或换小食。

## 4. 对比表输出模板

向用户展示方案时用如下结构（金额一律「元」，两位小数）：

```
方案          含券            到手价      比基准省
─────────────────────────────────────────────
基准（无券）   —              ¥59.90      —
方案A         满50减10券       ¥49.90      ¥10.00
方案B         8.8折券          ¥52.71      ¥7.19
方案C         满50减10+凑1件   ¥54.80*     ¥5.10（多1件）
─────────────────────────────────────────────
推荐：方案A（到手最低）
*方案C含额外加购商品
```

要点：
- 永远先给「基准无券价」作锚。
- 标注每方案用的是什么券、是否适用。
- 含凑单/加购的方案要注明「多买了什么」，让用户自己权衡。
- 推荐语写清理由（最低 / 最贴合预算 / 券易得），不替用户拍板。

## 5. 常见省钱误区（提醒用户 / 自查）

- **只看券面额不看门槛**：满减券未达门槛 = 用不了，先算总额。
- **忽略分→元换算**：把返回的分当元，导致报价差 100 倍。
- **默认全排列试券**：商品/券多时算力爆炸，受控试 2~3 个高概率组合即可。
- **擅自领券/下单**：领券消耗额度、下单涉及真实资金，必须用户确认。
- **编造券码**：couponId/couponCode 必须来自 available_coupons 或已领券，不得臆造。
- **漏传 beCode**：得来速/外送/团餐场景下 beCode 缺失会直接报错，先取门店编码配对。
